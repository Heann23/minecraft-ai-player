# Goal 선택 경험 준비와 개발용 모델 후보

개발자용 경험 준비·오프라인 후보 학습·내보내기 도구다. 사용자 서버에 Python 설치나 학습을 요구하지 않는다. 플러그인의 실제 판단과 실행권을 바꾸지 않는다. 경험 준비와 첫 후보 학습은 표준 라이브러리만 쓰고 ONNX 내보내기는 선택적 개발 의존성을 사용한다.

```powershell
python export_experience.py <training-data-folder> --goals <matching-source>/GoalType.java --output <new-output-folder>
```

현재 Experience/Observation v1만 받는다. 에피소드 시작·종료, 판단 ID, 실제 행동·결과 연결, 기록 개수를 확인한다. 손상·지원하지 않는 스키마·연결 누락이 있는 에피소드는 통째로 제외하고 오류를 남긴다. 종료되지 않은 수집 중 파일은 최종 데이터로 사용하지 않는다. 오류가 있으면 종료 코드 2를 반환한다. 기존 출력 폴더를 덮어쓰지 않는다.

자율 Teacher 판단만 Goal 선택 표본으로 내보낸다. 사용자 요청·강제 목표, 갇힘 회복용 대체 계획, Teacher와 실제 실행 목표가 다른 표본은 제외하고 개수를 보고한다. 입력은 결정 당시 Observation이다. Teacher 점수·이번 실행 계획·미래 결과·Shadow 출력을 입력에 섞지 않는다. 실패·중단 판단의 라벨은 성공으로 바꾸지 않으며 `result` 메타데이터로 구별한다. 훈련 코드는 이 메타데이터를 feature로 쓰면 안 된다.

`goal-ids.json`은 해당 플러그인 소스의 enum 순서를 고정한 출력 대응표다. `train.jsonl`, `validation.jsonl`, `test.jsonl`은 seed 문자열 SHA-256의 앞 8자 정수 modulo100으로 70/15/15 버킷을 배정한다. 같은 seed의 모든 AI·재실행·리스폰은 같은 쪽에 속한다. 이는 데이터 누출을 막는 배정 규칙이며 실제 표본 비율이나 미사용 월드 평가 성공을 보장하지 않는다. 개발 서버의 동일 시드에 모두 배정된 작은 시험 자료는 모델 평가군이 아니다.

`audit.json`에 원본 해시·스키마·버전·seed·종료 원인·제외/오류·Goal/결과/분할 표본 수를 남긴다. 입력 파일 경로와 AI 이름은 산출물 메타데이터에 복사하지 않는다. Observation에는 AI 좌표와 월드 상태가 포함되므로 실제 자료는 공개 저장소에 추가하지 않는다.

현재 `readyForTraining`은 항상 false다. 충분한 서로 다른 seed와 Goal 표본, 고정 평가군, 비학습 기준선 비교가 필요하다. 이후 첫 목표 선택 모방학습·ONNX export·Java Shadow 연결로 확장한다. Goal 선택 모델이 Skill 내부 동작까지 학습했다고 보고하지 않는다.

숫자 입력 준비:

```powershell
python prepare_features.py <export-output-folder> --output <new-feature-folder>
```

`goal_features.py`는 Observation v1의 몸 상태·인벤토리·환경·진행·기억과 판단 직전 목표를 고정된 순서로 변환한다. 연속값은 계약에 적힌 상수로 나누고 0~1로 제한한다. 학습·평가 자료 전체에서 평균이나 분산을 추정하지 않는다. 범주값은 명시된 순서의 one-hot이다. 절대 좌표·tick·시각·seed·이름·자유문자열·Teacher 점수·미래 결과는 입력에 포함하지 않는다. Observation의 모든 세부 정보가 표현되는 모델은 아니며, 생물 종류·장비/효과·바이옴 등은 현재 제외한다.

없는 아이템 종류의 개수는 0이다. 거점을 모르면 거점 거리도 0으로 표현하고 별도 `homeKnown` 값으로 구분한다. 나머지 선택 필드가 없거나 숫자가 유한하지 않거나 범주가 지원 목록 밖이면 거부한다. 새 Observation 스키마나 Goal 순서가 나오면 기존 계약을 조용히 재사용하지 않는다.

`feature-contract.json`에는 순서·정규화 상수·Goal 대응표·원본 Goal 소스 해시가 들어 있다. `feature-report.json`에는 계약 해시·입력 분할 파일 해시·표본/seed/Goal 개수·오류가 들어 있다. seed 분할이나 감사 계약이 맞지 않는 자료는 오류 종료하며 부분 학습 자료를 생성하지 않는다. 숫자 파일의 `x`만 입력이며 라벨·seed·원본 해시·결과는 분할/평가 메타데이터다. 변환 성공은 학습 완료나 모델의 성능을 뜻하지 않는다.

첫 개발용 모방학습 후보:

```powershell
python train_goal_bc.py <feature-folder> --output <new-candidate-folder>
```

표준 라이브러리로 작은 선형 softmax 모델을 훈련한다. 고정된 난수 시드·80 epoch·학습률 0.05를 사용하고 성공한 train 표본만 가중치 갱신에 넣는다. 실패·중단·계획 없음의 제외 개수를 기록하며 이를 성공으로 바꾸지 않는다. 클래스 빈도의 제곱근 역수로 학습률을 가중한다. validation/test는 가중치 갱신·정규화·하이퍼파라미터 선택에 사용하지 않는다. 지원 Goal은 성공한 훈련 표본에 존재한 종류만이다.

`candidate.json`은 실제 학습한 가중치·bias·지원 Goal ID·입출력 계약·학습 방법을 담는다. `evaluation.json`은 파일/계약/가중치 해시, 훈련 seed·표본·지원/미지원 Goal과 각 분할의 Teacher 일치율을 담는다. 다수 클래스와 직전 Goal 반복 기준선도 비교한다. Teacher 일치율은 게임 생존 성공률이나 드래곤 처치 능력이 아니다. 평가에서 훈련되지 않은 Goal도 오답으로 계산한다. 이 후보는 항상 `deployable: false`이며 자동 배포하지 않는다.

현재 Java 추론·Shadow 연결은 없다. 모델 누락/불일치 fallback·지연/안전·미사용 월드 실제 평가를 구현해야 한다. 게임 서버의 Teacher 실행권과 기본 설정은 이 도구로 바뀌지 않는다. raw 경험·숫자 데이터·가중치 산출물은 공개 Git에 포함하지 않는다.

ONNX 후보 내보내기와 실제 CPU 추론 비교:

```powershell
python -m pip install -r requirements-onnx.txt
python export_goal_onnx.py <candidate-folder> --features <frozen-feature-folder> --output <new-model-folder>
```

`export_goal_onnx.py`는 같은 후보/입출력 계약/훈련·평가 파일 해시를 확인하고 ONNX opset13·IR8의 MatMul/Add/ArgMax 그래프를 만든다. 입력은 float32 `[batch, featureCount]`, 출력은 float32 logits와 int64 Goal ID다. 미학습 Goal은 가중치를 0으로 하고 bias -1e9로 마스킹해 지원 Goal만 고른다. 실제 CPU 추론에서 고정 자료의 Goal ID와 지원 Goal logit을 원본 후보와 비교하며, 불일치가 있거나 절대 오차가 1e-4를 넘으면 실패 종료한다.

모델·원본 후보·feature/Goal·분할·도구 해시, 런타임 버전·OS·CPU provider·입출력·지원 ID·오차와 단일 입력 지연을 `model-manifest.json`에 남긴다. 산출물은 `goal-candidate.onnx`와 계약/manifest다. 수치 동등성은 후보 품질 개선이나 Java/Paper 호환성을 증명하지 않는다. 이 단계도 `deployable: false`, `executionAuthority: none`이며 JAR에 모델을 넣거나 자동 승격하지 않는다. Java 추론·Shadow·fallback·지원 환경 검증은 후속이다.

API 근거: [ONNX 공식 Python 문서](https://onnx.ai/onnx/intro/python.html), [ONNX Runtime 공식 Python API](https://onnxruntime.ai/docs/api/python/api_summary.html).


## 실제 Paper 경험으로 학습하는 RL 정책 — 전환 중

2026-10-26 사용자 지시로 새 경로는 Teacher Goal 모방이 아니라 실제 행동/인자의 선택을 학습하는 PPO입니다.
위 Goal BC/ONNX 도구와 후보는 과거 개발 경로이며, 새 actor의 학습 자료나 배포 Brain으로 자동 재사용하지 않습니다.

`rl_actor.py`는 관측128+파라미터 후보256의 공유 actor와 별도 value 네트워크를 학습합니다. 동일 행동 정책 버전의
실제 전이만 PPO 갱신에 사용하고, 경과한 실제 서버 틱의 할인·에피소드/순서 누락·여러 AI의 GAE를 구분합니다.
Goal 정답이나 Teacher 점수는 필요하지 않습니다. 초기 무작위 가중치는 학습 모델로 내보낼 수 없습니다.

`PpoBridge`/`train_paper_ppo.py`는 전용 로컬 개발 폴더에서 값 JSON을 교환하는 전송/훈련 프로토콜입니다.
메인 스레드는 월드 관측/입력 실행을 담당하고, 파일 I/O는 별도 쓰레드에서 수행하도록 준비했습니다.
트레이너는 실제 실행을 확인한 전이를 받아야 갱신하며, 서버/월드를 시작하거나 가상 게임 경험을 만들지 않습니다.
모델 초기화와 numerical fixture 테스트는 Minecraft에서 학습했다는 근거가 아닙니다.

필요한 개발 의존성은 `requirements-rl.txt`의 NumPy입니다. 출력은 새 비공개 폴더로 한정하고 학습 결정 수/원본 기록 용량을
명시적으로 제한합니다. Brain의 전이/보상/종료와 브리지 연결 소스는 구현했지만 격리 훈련 환경·reset과
실제 게임 수용·미사용 월드 평가는 미완료입니다. 학습 프로세스를 실행해 기다리는 것만으로 실제 RL 훈련이 되는 것은 아닙니다.

호환 출력을 만들 때는 `minecraft-rl-actor/v1`에 실제 환경 스텝·run ID·원본 전이 해시를 기록합니다.
학습 후에도 생존/진행 성능과 모든 월드 자율은 별도 실제 평가가 필요하며, `evaluationComplete`와
`allWorldAutonomyProven`을 근거 없이 true로 바꾸지 않습니다. 사용자 서버는 최종 학습 모델의 추론만 수행하는 제품 목표를 유지합니다.


### 게임 연결 구현 상태

Brain과 개발 브리지 연결을 구현 중입니다. `policy.mode: training`은 `policy.allow-training: true`를
명시한 경우에만 활성화하고, 학습 연결과 학습 완료를 구분합니다. 학습 프로세스나 Paper 서버를 자동 시작하지 않습니다.
관측 시점과 실제 입력 적용 시점을 따로 남겨 추론 대기 시간을 실행 시간으로 꾸미지 않습니다.
각 전이에는 실제 다음 상태·종료/잘림·환경/에피소드/순서·정책 버전을 포함하고 재전송 확인을 중복 경험으로 쓰지 않습니다.
행동을 얼마 동안 유지한 뒤 다시 판단할지도 5/20/80/600틱 후보에서 모델이 고릅니다.
이는 채굴 입력 유지를 매 틱 우연히 반복 선택해야 하는 문제를 줄이는 명시적 행동 인자입니다.

보상 `survival-progress/v1`은 실제 생존 시간·체력 변화·에피소드 내 처음 소지한 품목·사망·
실제로 AI에게 귀속된 엔더드래곤 사망으로 계산합니다. 사람이 정의한 목적이며 편향이 없다고 주장하지 않습니다.
Teacher 정답 라벨이나 Goal 순서는 사용하지 않습니다. 보상만으로 숨기/품목 수집에 치우칠 가능성은
실제 미사용 월드 평가에서 살펴봐야 합니다. 현재 지원 행동/관측 표현은 모든 Minecraft 상호작용을 포함하지 않습니다.


### 실제 실행 이력과 학습 재개

2026-10-26 재개 요청 및 격리 서버 수집·훈련·미사용 월드 평가 허가 후 Paper140의 새 normal survival 월드에서
전이128개로 첫 PPO 모델을 생성했습니다. 이 규모는 학습 경로 연결 근거이며 숙련된 플레이 능력의 근거가 아닙니다.
첫 미사용 시드의120초 평가에서는 greedy argmax 실행의 장착 반복/무진행이 관측됐습니다. 실패를 보존하고,
제품 실행을 PPO와 같은 가중치 기반 categorical 선택으로 맞췄습니다. 무작위 초기 모델을 제품 모델로 간주하지 않습니다.
PPO 최적화는 별도 파라미터 복사본에서 수행하고, 그동안 게임의 행동 샘플링은 고정된 기존 가중치로 계속합니다.
완료된 갱신만 새 정책 버전과 원본 전이 해시/사용 바이트를 함께 게시합니다. 절대 좌표/엔티티 UUID 등의 실행 식별자는
학습 특징에 해시해 넣지 않고 파라미터 ID 메타데이터와 상대 위치/실제 효과 관측을 구분했습니다.
수학/프로토콜 테스트의 임시 숫자 모델은 실제 Minecraft 학습 모델이 아닙니다.

훈련기는 갱신 완료 시 배포용 actor와 별도로 `optimizer-checkpoint.json`을 저장합니다. actor/critic·Adam1/2차 모멘트·
갱신 번호·정책 버전·난수 상태를 포함하며, 배포 actor만으로 PPO를 재개하지 않습니다. `--resume`은 체크포인트와
보고서의 해시/버전 및 학습에 사용한 원본 전이 prefix 해시를 확인하고 새 출력 폴더에서 이어갑니다. 이전 전이를
다시 on-policy 표본으로 사용하지 않으며, 부모 체크포인트/훈련 run/누적 스텝을 새 결과의 `parents`로 남깁니다.
재개 후 새 갱신이 없으면 새 학습 artifact를 만들지 않습니다. 기존 optimizer 정보가 없는 첫 actor를 억지로 변환하지 않습니다.

Python 훈련기의 `--max-transitions`는 이번 run의 추가 전이 예산이며, 재개 결과의 `environmentSteps`는 부모를 포함한
누적 수, `runEnvironmentSteps`는 이번 run의 수입니다. `actualServerTicks`는 이번 run의 실제 틱으로 이전 틱을 추정하지 않습니다.
체크포인트 출처 검사는 실제 Minecraft 숙련도/안전성 평가를 대신하지 않습니다. 실제 훈련·평가 seed의 분리와
관측/행동 지원 범위·장기 기억, 모든 월드 일반화는 여전히 미완료입니다. 수치 테스트는 별도 임시 fixture입니다.

현재 입력 계약은 `minecraft-primitive-candidates/v4`, 전송은 `minecraft-paper-ppo/v2`입니다. v2에서 추가한64개 관측은
보이는 인접12칸의 known/solid/water/lava와 현재 위치·동일 틱·완료 범위의 생물 관측, 피격 무적 시간/수평 속도입니다.
보이지 않음·로드 안 됨·예산 중단·과거 엔티티 scan은 별도의 미확인 상태로 둡니다. 아직 전체 주변 공간·장기 기억이 아닙니다.
`--resume ... --upgrade-context` 또는 아래 명시 세션 이전으로 v1/v2/v3의 PPO 체크포인트를 v4로 이전합니다. 기존 actor 관측64/128과 action256 사이 및 critic의
뒤에 새 관측128/64의 가중치/Adam 모멘트0을 삽입합니다. 기존 예측/가치·버전·누적 학습·난수 상태를 보존하고 부모 출처에
이전을 기록하며, 새 입력을 이미 학습했다고 주장하지 않습니다. v1 actor 단독의 자동 변환/직접 적용은 지원하지 않습니다.

### 격리 실행 도구

`paper_lab.py`는 명시적으로 실행할 때만 전용 localhost Paper 서버와 선택한 훈련기를 시작합니다. 모델·훈련 전이는
Git에 넣지 않습니다. 계획 JSON의 형식은 `minecraft-paper-seed-plan/v1`이며, `trainSeeds`와 `evaluationSeeds`에
서로 겹치지 않는 signed64 정수의 정규 십진 문자열 목록을 지정합니다. 선택한 seed가 다른 분할이면 실행을 거절합니다.
정수 문자열을 사용해 JSON의 큰 정수 손실·서버의 문자열 해시 seed와 혼동하지 않습니다.

필수 인자는 `--plan`, 새 `--output`, `--paper`, 실행용 `--plugin`, `--java`, 이미 동의된 `--eula`,
캐시 라이브러리 폴더 `--runtime-cache`, `--mode train|evaluate`, `--world-seed`, 전체 `--source-commit`,
전용 `--port`, 유한 `--seconds`입니다. 훈련은 추가 전이 한도 `--steps`와 선택적인 `--resume`, 평가는
고정된 `--model`을 받습니다. 평가는 훈련기를 실행하지 않습니다. 이 도구가 사용자를 대신해 EULA에 동의하지 않습니다.

매번 새 survival/normal 월드를 생성하며 과거 월드/플러그인 상태를 복사하지 않습니다. 시작 시에만 AI를 생성하고
정상 입력으로 플레이합니다. 생존 중 아이템 지급·순간이동·블록 직접 변경·Teacher 목표 강제는 하지 않습니다.
source/JAR/설정/도구/계획/모델 해시·프로세스 ID·로그·종료 상태를 보존합니다. 부모 체크포인트를 사용하는 실행도
같은 계획의 훈련 분할인지 확인합니다. 예산 종료 시 소유한 자식 프로세스만 종료하고 월드/실패는 삭제하지 않습니다.
`observed-gameplay.json`은 주기적 위치/체력/허기, 행동 선택/입력 종료·사망·거절과 최종 소지품의 관측 요약입니다.
누락은 미확인으로 남기며, 입력 SUCCESS를 생존/자원/제작 목표의 달성으로 바꾸지 않습니다.

PPO 갱신에서 제외한 이전 정책 버전/최적화 중/예산 이후 전이는 `discarded-transitions.jsonl`에 실제 원본과 사유를
남깁니다. 사망/실패를 성공으로 바꾸거나 삭제하지 않으며, 학습에 사용한 `paper-rollouts.jsonl`과 그 prefix 해시는
별도로 유지합니다. 원본과 제외 기록의 총량에 용량 한도를 적용합니다. 수학용 임시 fixture와 실제 실행은 구분합니다.
체크포인트/훈련 초기화가 실패하면 Paper를 시작하지 않습니다. 준비 전 서버에 게임 명령을 보내지 않습니다.

`--start-time 0..23999`는 AI를 생성하기 전 실험 월드의 시작 시간을 준비합니다(기본0). 설정과 실제 콘솔 명령을
남기고 플레이 중에는 시간을 바꾸지 않습니다. 야간 훈련 등도 훈련 분할의 별도 월드로만 수행하며 평가 실패 월드를
훈련 월드로 재분류하지 않습니다. 이 초기 환경 준비는 정책에 정답 행동을 주거나 생존 결과를 보장하는 기능이 아닙니다.

새 월드를 더 학습할 때는 이전 계획 파일을 덮어쓰지 않고 별도의 확장 계획을 만듭니다. 재개 시 부모 계획의 해시를
원본 파일과 확인하고, 과거 train/evaluation 시드 전체가 같은 분할에 유지되는 확장만 허용합니다. 평가 시드를 훈련으로
이동하거나 이전 실패 월드를 목록에서 지우는 변경은 거절합니다. 새 실행에 부모 계획 해시도 남깁니다.

명시적 중지에는 해당 실험 출력의 `stop.request` 파일을 생성합니다. 실행기는 정상 게임 종료 전이와 서버 저장을
먼저 처리한 뒤 훈련기에 중지를 요청합니다. 훈련기는 완료 중인 갱신을 저장하고 미완성 버퍼는 원본으로 보존합니다.
중지 때문에 미완성 자료를 새 학습 완료로 표시하지 않습니다. 정해진 종료 기한을 넘긴 소유 자식만 강제 종료하고
그 사실을 결과에 기록합니다. 요청 파일을 지워 자동 재개하거나 다른 서버/훈련 프로세스를 종료하지 않습니다.

에피소드별 진단은 episode-outcomes.jsonl에 실제 고유 전이 전체(정책 버전 때문에 PPO에서 제외된 전이 포함)의 수·서버 틱·보상·최소 체력 비율·정책 버전·사망/잘림·누락 순서를 남깁니다. 학습 raw 사용 수와는 별개입니다. 종료가 관측되지 않았거나 중간 순서가 빠졌으면 완전한 생존 기록으로 표시하지 않습니다. 훈련기 종료 시 열려 있던 에피소드도 미완료로 보존합니다.


완료된 갱신은 checkpoints/version-*의 불변 묶음(actor/optimizer/report/manifest)으로 보존하고 파일 저장을 동기화한 뒤 latest-checkpoint.json을 원자적으로 갱신합니다. 예전 세대와 미완성 임시 디렉터리를 덮어쓰지 않습니다. 원본 전이도 묶음 게시 전에 디스크에 동기화합니다. 루트의 세 파일은 기존 도구용 별칭이며 복구 기준은 아닙니다.
--resume에 훈련 출력 디렉터리를 지정하면 포인터와 묶음의 모든 해시 및 실제 원본 prefix를 검증하고 손상된 최신 세대는 건너뛰어 마지막 정상 세대를 명시적으로 보고합니다. 명시한 체크포인트 파일은 기존처럼 정확히 검사하고 몰래 다른 파일로 바꾸지 않습니다. 복구 불가 시 초기화하지 않고 중지하며 손상/과거/임시 파일은 보존합니다. 구형 flat 체크포인트의 검사/명시 이전도 유지합니다.


Windows에서 브리지 파일의 원자 교체/삭제가 일시 잠기면 동일 응답을 보존해 재시도합니다. 파일 정리 실패 때문에 같은 요청을 다시 학습하거나 다른 행동으로 샘플링하지 않습니다. Java의 요청 ID/관측 시효/선택 인자 재검사는 유지합니다.


두뇌 ID는 새 초기화 시 생성하고 이후 월드/훈련 run/체크포인트 재개가 바뀌어도 유지합니다. 기존 자료에 ID가 없으면 보존된 계보의 최초 훈련 run을 명시적 식별자로 사용합니다. 새 artifact/optimizer/report와 응답 메타데이터에 실제 정책 버전·가중치 갱신·학습 당시 시작 방식·저장 상태를 기록합니다. 수집 전이와 실제 학습/성능을 구별합니다. 인게임 /ai stats [이름]은 고정 모델 또는 최근 수신한 학습 프로세스 상태와 수신 경과 틱을 표시합니다. 구형 모델에 없는 카운터를0/성공으로 꾸미지 않습니다. 학습 상태 전환·모델 관리와 선택적 관리형 자동 복원의 현재 범위는 이후 절에 정리합니다.


백엔드의 시작 가중치와 학습 여부는 독립 인자입니다. --start-state fresh는 새 초기화, pretrained/resume은 검증된 전체 체크포인트 참조를 요구합니다. --inference-only는 같은 actor/critic의 가중치·최적화 카운터를 고정한 채 추론하며, 이때 들어온 전이는 learning-disabled로 별도 보존하고 나중에 학습으로 전환해도 소급 재사용하지 않습니다. Fresh+Inference의 초기 무작위 모델을 훈련 완료 artifact로 내보내지 않습니다. --max-decisions로 추론도 유한 예산을 두며, 미지정 시 전이 한도의16배/최소1000 결정입니다. 이 선택은 백엔드 시작 인자와 이후 절의 명시 전환·관리형 세션 복원에 연결됩니다.


Fresh 생성 직후에도 초기 가중치·가치망·최적화0상태/난수/두뇌ID를 initializationOnly 체크포인트로 보존합니다. 같은 네트워크 구조이며 학습하지 않은 상태입니다. 초기 actor는 별도 minecraft-rl-initial-actor/v1 형식으로 묶음 안에만 저장하며 배포용 루트actor로 게시하지 않습니다. 명시 Resume는 초기 상태도 동일 가중치로 복원할 수 있으나 Pretrained 선택은 이를 거절합니다. 학습 이력이 있는 디렉터리의 정상 학습 세대가 모두 손상되면 초기0세대로 몰래 복구하지 않고 중지합니다.


백엔드는 runtime-session.json에 두뇌ID·정확한 체크포인트 해시/참조·학습 활성화·정책/최적화 카운터·현재 난수 상태를 체크섬으로 묶어 저장합니다. 모델 게시·정상 종료 및 설정된 주기(--session-save-seconds 기본30초)에 저장합니다. --restore-session으로 같은 모델/난수/학습꺼짐 상태를 복원할 수 있고, 잘못된 해시/다른 두뇌/다른 가중치를 만나면 새 초기화 없이 거절합니다. 명시적으로 이전한 계약 정보도 보존합니다. 미완성 rollout은 원본에 보존하되 학습 완료로 계산하지 않으며 재시작에 소급 혼합하지 않습니다. 위치/인벤토리/AI실행 의사는 별도 월드/플레이어 저장이 담당합니다. 이후 절의 선택적 관리형 백엔드 시작·이름 관리·학습전환과 연결되며 모든 월드 성능 수용을 뜻하지 않습니다.


연결된 공유 두뇌는 /ai training on|off로 같은 모델의 학습 여부를 전환할 수 있습니다. 모든 AI의 정책 입력을 잠시 정지하고 실제 마지막 전이의 수신을 확인한 뒤, 같은 brainId에만 제어 요청을 보냅니다. 이미 진행 중인 최적화는 끝까지 확인하고 학습 설정을 세션에 저장한 뒤 응답합니다. 서버 메인 스레드는 기다리지 않습니다. 응답 ID/brainId/원하는 상태/버전/가중치 hash를 확인하며, 같은 요청의 파일 잠금 재시도는 같은 결과를 반환합니다. 중간에 AI를 명시 정지해도 전환 완료가 AI를 다시 켜지 않습니다. 연결된 Python 런타임이 없는 Java 고정 추론에서 학습 on은 현재 거절하며, 모델 등록·백엔드 자동 시작 통합은 후속 단계입니다. mode 전환은 새 가중치 초기화가 아니고 평가 실패를 성능 개선으로 바꾸지 않습니다.

이름으로 관리하는 개발용 모델 목록은 `model_catalog.py`를 사용합니다. 새 네트워크 구현이 아니라 기존 전체 체크포인트와 세션의 검증된 참조입니다. 모델 이름은 소문자 영숫자/밑줄/하이픈 1~64자로 제한합니다. 상대 파일을 옮기거나 삭제하면 해당 모델을 사용할 수 없으며, 가중치/원시 전이/부모 계보를 함께 보존해야 합니다.

```text
python training/model_catalog.py --catalog <private-catalog> import survival-v1 --checkpoint <training-directory> --learning off
python training/model_catalog.py --catalog <private-catalog> save survival-v1 --session <runtime-session.json>
python training/model_catalog.py --catalog <private-catalog> list
python training/model_catalog.py --catalog <private-catalog> info survival-v1
python training/model_catalog.py --catalog <private-catalog> select survival-v1
python training/model_catalog.py --catalog <private-catalog> restore survival-v1 --output <new-session.json>
python training/model_catalog.py --catalog <private-catalog> new fresh-v1 --output <new-initial-directory> --seed 777 --learning off
```

`new`는 실제 ActorCritic의 초기 가중치·최적화0상태를 보존할 뿐 학습하거나 서버를 시작하지 않습니다. `import`는 실제 학습 이력이 있는 PPO 체크포인트만 허용합니다. `save`는 불변 세션 개정본을 쓴 뒤 이름 참조를 원자 교체합니다. 같은 이름에 다른 두뇌·오래된 정책·동일 버전의 다른 가중치/최적화를 덮어쓰지 않습니다. 선택은 이름과 두뇌 ID를 보존하며, 읽기 실패·손상·기존 작성 잠금을 새 초기화로 우회하지 않습니다. 준비된 전환 시나리오의 모델과 그 후속 체크포인트는 자율 모델 목록 등록을 거절합니다.

백엔드의 기존 실행 인자에 `--catalog <private-catalog> --restore-model survival-v1`을 추가하면 같은 두뇌/가중치/최적화/난수/학습 설정을 복원합니다. 모델 이름을 생략하면 저장된 선택을 사용합니다. `--resume`, `--restore-session`, Fresh 선택과 함께 사용할 수 없습니다. 목록은 실행 중인 프로세스를 자동 교체하지 않으며, 실행 이후 모델/세션 저장은 명시적인 `save`로 등록합니다. 격리 실행 도구도 같은 인자를 지원하고 서버 시작 전에 선택한 세션을 고정하여 중간 목록 변경이 실행 모델을 바꾸지 않게 합니다. 명시 모델 관리와 선택적 관리형 시작·정상 재시작은 이후 절의 구현 범위이며, 모델 목록 자동 갱신과 손상 세션 복구는 남았습니다.

연결된 개발 백엔드에 `--model-catalog <private-catalog>`를 명시하면 관리자용 `/ai model list`, `/ai model info <이름>`, `/ai model save <이름>`을 사용할 수 있습니다. 고정 추론과 학습 모두 동일 백엔드에서 처리하며, 먼저 `/ai stats`에 실제 두뇌 ID가 수신되어 있어야 합니다. Java만으로 추론 중이거나 목록 경로를 지정하지 않았다면 관리 명령은 거절합니다. 기존 `/ai brain` 진단과 `/ai save` 플레이어 상태 저장은 그대로 사용합니다.

목록/조회는 실행 행동을 취소하거나 활성 정책의 메타데이터를 오래된 값으로 덮어쓰지 않습니다. 저장은 같은 공유 두뇌의 마지막 전이 수신·진행 중 갱신·세션 저장을 확인한 뒤 같은 이름 관리기에 등록합니다. 메인 스레드는 파일 I/O를 기다리지 않으며, 응답 ID/명령/이름/두뇌/카운터를 확인합니다. 정지한 AI를 다시 시작하거나 선택 모델을 교체하지 않습니다. 준비된 시나리오의 스냅샷 저장은 자율 모델 목록에서 거절합니다. 목록은 32개까지 표시하며 손상 항목을 사용 불가로 표시합니다. 신규/불러오기·선택적 관리형 설정과 정상 재시작은 이후 절에 연결하며, 모델 목록 자동 갱신·손상 세션의 마지막 정상 복구는 남았습니다.

일반 격리 백엔드 실행에는 `--model-catalog <private-catalog> --save-model-at-end <name>`으로 플레이 종료 시점의 두뇌를 저장할 수 있습니다. 특정 행동을 시키는 시나리오가 아니라 정상 종료 경계의 저장이며 `--scenario`와 함께 사용할 수 없습니다. 명령 전달만으로 성공이라 쓰지 않고, 비동기 완료 응답을 기다린 뒤 같은 두뇌의 체크포인트/원본/카운터를 검증해 결과에 별도로 기록합니다. 응답/검증이 없으면 저장 미확인으로 남깁니다. 실제 서버 시작/훈련/모델 적용은 여전히 별도의 사용자 승인 범위에서만 수행합니다.

선택적 개발 백엔드는 `policy.runtime.enabled: true`와 Python 실행 파일·동일 소스의 `train_paper_ppo.py` 경로·기존 모델 목록을 명시하면 플러그인이 직접 실행 과정을 소유합니다. 기본은 꺼져 있고 일반 사용자 설치의 Java 추론 경로는 그대로입니다. Python/NumPy와 개발 학습 소스는 이 기능에만 필요하며 JAR에 자동 포함하거나 설치하지 않습니다. 목록/runs/통신 저장 경로는 플러그인 데이터 폴더 안에 두고, `runtime.model`은 최초 선택에만 사용합니다. 빈 값이면 저장된 목록 선택을 사용합니다. 모델이 없다고 Fresh로 초기화하지 않습니다.

이후 시작은 `brain-runtime/current-session.json`의 정확한 이전 세션을 우선하며 같은 두뇌·모델·난수·학습 설정을 복원합니다. `allow-training: false`이면 고정 추론을 강제하고 인게임 학습 on도 거절합니다. true여도 저장된 off를 on으로 바꾸지 않습니다. 준비가 확인된 뒤 저장된 AI 플레이어를 복원하며 백엔드 준비 실패 시 기존 플레이어 저장본을 그대로 둡니다. 세션은 `runtime.session-save-seconds` 주기로 저장되고 매번 새 run과 통신 디렉터리를 사용합니다. 소유 잠금이 있는 다른 런타임을 시작/종료하지 않습니다. 종료는 자신의 백엔드에 정상 중지를 요청하고, 백엔드가 예기치 않게 끝나면 AI를 정지합니다. 손상된 세션 참조는 보존하고 자동 초기화로 우회하지 않습니다.

이 연결은 격리 Paper140에서 플러그인의 최초 자동 시작과 같은 월드 재시작을 실행했습니다. 같은 두뇌/체크포인트/정책 버전/갱신 횟수/학습off와 시작 전 난수 상태를 복원하고, 새 통신 경로에서 추론하며 정상 종료했습니다. 이 사례는 플레이어 상태 저장을 끈 환경이므로 AI 플레이어의 명시 정지 재시작 수용과 다릅니다. 인게임 신규/불러오기, 모델 목록 자동 갱신, 명시 정지의 재시작 수용·비정상 종료 직전 별도 영속화와 손상 세션의 마지막 정상 세대 복구는 남았습니다. 위 자동 세션 참조를 이름 목록의 자동 갱신이나 모든 월드 게임 능력 수용으로 해석하지 않습니다.

격리 도구의 `--managed-backend --catalog <private-catalog> --inference-only`는 별도 외부 trainer를 실행하지 않고 플러그인이 직접 백엔드를 시작하는 경로를 확인합니다. 기존 선택의 검증된 세션 참조만 격리 플러그인 목록에 등록하고, 실제 두뇌 준비 응답 뒤 플레이를 시작합니다. 현재 이 수용 경로는 추론 전용이며 학습/서버 재시작 수용을 대신하지 않습니다. 중첩된 plugin/runtime 경로와 세션 복원에서도 준비된 자료의 사용 제한을 계승합니다.

플레이어 상태 저장이 켜져 있으면 사용자 명령/허용된 대화의 시작·정지 의사를 `execution-intents`에 따로 저장합니다. 위치/인벤토리/월드 상태를 다시 저장하는 작업이 아니며, AI 개체별 executionId로 같은 이름의 재생성도 구분합니다. 예전 저장에는 이름에서 얻는 안정된 이전 형식 ID를 적용하고, 최신 의사 기록이 있으면 플레이어 snapshot의 running보다 우선합니다. 모델 연결 실패로 잠시 정지하거나 저장본에서 자동 재개할 때는 사용자의 의사를 덮어쓰지 않습니다.

의사는 별도 파일 작업 스레드에서 체크섬·파일 동기화·원자 교체로 저장하며, 뒤늦은 오래된 요청은 최신 기록을 덮어쓰지 않습니다. 정상 종료는 최신 대기 기록을 마저 저장합니다. `/ai status`와 `/ai stats`는 저장 중/완료/실패를 표시합니다. 물리적으로 AI가 멈췄다는 응답만으로 디스크 저장 완료를 주장하지 않으며, 저장 완료 전에 서버가 강제 종료되면 마지막 요청까지 보존했다고 보장하지 않습니다. 손상된 의사는 원본을 보존하고 정지로 복원합니다. 실제 격리 정상 재시작에서 같은 AI 개체/정지 의사/인벤토리/두뇌/학습off를 복원하고 자동 시작·정책 샘플링이 없음을 확인했습니다. 최초 판정 도구의 콘솔 색상 비교 실패는 원본과 함께 보존하고 색상만 제거한 같은 로그의 재판정으로 구분했습니다. 오래된 running snapshot과 최신 stop의 제어된 서버 강제 종료 수용은 다음 사례로 구분합니다.

추가 격리 사례에서는 `save-all flush`로 running 플레이어 snapshot을 남긴 뒤, 별도 stop의 디스크 저장을 확인하고 자신이 시작한 Java 서버만 강제 종료했습니다. 원래 snapshot과 의사를 직접 수정하지 않았으며, 재시작 시 같은 개체의 최신 stop이 우선하고 자동 시작/정책 샘플링이 없음을 확인했습니다. 모델/학습off도 유지했습니다. 이 사례는 서버 강제 종료 뒤 백엔드는 협력적으로 종료한 것이므로 전원 차단·진행 중 PPO·전체 월드/인벤토리 원자 복구 수용과 구분합니다.

`/ai model new <이름>`은 현재 모델을 유지하면서 별도 이름의 Fresh 초기 상태를 등록합니다. CLI와 같은 초기화/목록 코드를 사용하며 학습·샘플링·모델 선택/교체를 실행하지 않습니다. 새 ID, 정책 버전0, 갱신0, 학습off, initializationOnly를 표시하고 기존 이름 덮어쓰기는 거절합니다. 별도 초기화 난수는 현재 정책의 난수 흐름을 소비하지 않습니다. 이 등록은 사전 학습 모델 생성이 아닙니다. 정상 격리 실행의 `--create-model-at-end <이름>`은 실제 응답/초기상태/기존 선택 불변을 확인하며 save/시나리오와 함께 사용할 수 없습니다. 명시 load·선택 모델 교체와 자동 목록 갱신은 이후 절에 연결했습니다.


신규 등록은 격리 Paper140에서 실제로 실행해 완료 응답·새 ID/초기상태/버전0/갱신0/off 및 기존 선택 파일 불변을 확인했습니다. 기존 활성 두뇌는 ID와 갱신 횟수를 유지했습니다. 새 모델은 실행하거나 훈련하지 않았으며 정상 추론 중 등록만 수행한 사례입니다.

`/ai model load <이름>`은 실행 중 전이를 확인한 뒤 저장된 모델을 명시적으로 불러옵니다. 저장 모델의 가중치/가치망/Adam/난수/계보를 검증하고 별도 경험 기록을 준비한 다음, 하나의 활성 세션을 원자 교체합니다. 기존 학습 on/off와 AI 시작·정지 의사를 유지하며, 교체 완료 콜백에서 AI를 다시 시작하지 않습니다. 오래된 모델/같은 ID의 이전 교체 요청이 뒤늦게 도착해도 두뇌 ID와 교체 epoch로 새 모델의 학습/샘플링에 섞이지 않도록 거절합니다. 실제 전이가 있는 거절 요청은 사유와 원본을 별도 보존합니다.

로드 전 검증/세션 게시가 실패하면 기존 모델을 유지합니다. 교체가 실제 완료됐는지 통신으로 확인하지 못하면 AI를 정지하고 저장된 세션을 확인하도록 보고합니다. 명시적인 거절과 미확인 상태를 구분하며 새 랜덤 모델/Teacher로 대체하지 않습니다. 활성 세션에는 불러온 이름과 정확한 체크포인트를 저장합니다. 목록의 최초 기본 선택은 유지되더라도 서버 재시작은 실제 활성 세션을 우선합니다. 관리형 세션 참조 v2는 소유한 세션 경로를 가리키며, 현재 두뇌 ID/가중치는 그 체크섬 세션과 전체 optimizer 검증이 바인딩합니다. v1 참조도 읽어 정상 시작 후 v2로 갱신합니다.

모델을 여러 번 불러와도 실행 전체의 전이/결정/원시자료 예산은 초기화하지 않으며 교체 횟수도 제한합니다. 격리 수용은 `--admit-models`에 명시한 최대8개의 검증된 snapshot만 비공개 목록에 추가할 수 있습니다. 새 격리 런타임을 복사하기 전에 원본 크기와 저장 공간 여유를 확인해 부족하면 서버 시작 전 중지합니다. 이 load 연결의 실제 수용 범위는 다음과 같으며, 모델 목록 자동 갱신·손상 세션 복구·모든 월드 플레이 능력 수용과 구분합니다.

실제 교체/동시 정지/없는 모델 거절 사례는 실행했습니다. 첫 초기 모델의 정지 재시작에서는 가중치·난수·정지는 같았지만 불필요한 초기 체크포인트 복제로 파일 해시가 바뀌어 참조 보존 판정이 실패했습니다. 원본을 보존하고, 초기 모델의 상태가 그대로면 기존 체크포인트를 유지하도록 수정했습니다. 추론으로 난수가 진행되면 기존처럼 새 초기 세대를 저장하며 세션에도 최신 난수를 보존합니다. 수정 후 같은 checkpoint 해시·난수·정지 의사·인벤토리의 실제 재시작을 확인했고 최초 실패/원본 JAR/로그는 별도로 보존했습니다.

관리형 백엔드는 준비된 세션의 실제 정책 버전/갱신/수집 전이/학습 상태를 AI 복원 전에 전달합니다. 따라서 AI를 먼저 실행하지 않아도 정지 상태에서 stats와 모델 관리를 사용할 수 있습니다. 초기 메타데이터를 재사용할 때는 원래 수신 틱을 유지해 오래된 값을 방금 수신한 것처럼 표시하지 않습니다. 모델/학습 제어 응답은 확인한 상태로 갱신하며, 누락된 카운터를0으로 만들어 채우지 않습니다.

명시 로드의 실제 사례에서는 학습된 초기 모델에서 다른 Fresh 모델로 교체하며 동시 정지·명시 시작·없는 모델 거절을 확인했습니다. 교체 후 정상 재시작은 목록의 부팅 기본 선택으로 돌아가지 않고 실제 활성 모델을 복원했습니다. 별도 사례에서는 정지 AI를 먼저 실행하지 않고 학습된 체크포인트로 불러온 뒤, 명시 시작 후 고정 추론·다시 정지까지 확인했습니다. 파라미터/가치망/Adam/난수의 정확한 복원, 교체 전 요청 거절, 게시 실패의 기존 상태 보존은 원격 사례와 구분합니다. 새 실제 학습을 실행하거나 초기 모델을 훈련된 모델로 승격한 작업은 아닙니다.

이름으로 시작하거나 명시적으로 불러온 활성 모델은 런타임 세션을 저장한 뒤 같은 이름의 불변 개정/포인터도 갱신합니다. 학습 체크포인트 게시·주기 저장·학습 on/off·정상 종료에 연결되며, 동일 세션의 반복 저장은 새 개정을 만들지 않습니다. 부팅 기본 선택과 다른 이름의 별도 저장본은 바꾸지 않습니다. `save`로 별도 이름을 만들기만 한 경우 자동 갱신 대상으로 전환하지 않으며, 그 이름을 명시적으로 불러오면 활성 이름이 됩니다.

이름의 기존 두뇌·더 최신 가중치/수집 횟수를 덮지 않으며 사라진 이름을 자동 재생성하지 않습니다. 모델 교체를 준비하는 동안에는 목록을 갱신하지 않고 활성 세션 게시 이후에만 반영합니다. 준비된 제어 시나리오 자료는 계속 제외합니다. 목록 잠금·쓰기·검증 실패는 런타임의 저장 완료를 취소하거나 학습 flag를 되돌리지 않습니다. 백엔드 stderr와 `catalog-sync.json`에 실패를 기록하고 다음 저장 때 재시도합니다. 상태 metadata의 `catalogSyncState`는 런타임 체크포인트 저장 상태와 별개입니다. 불변 개정은 보존하며 이름 목록의 예산은 개정 수가 아닌 모델 이름 수에 적용합니다. 자동 갱신은 격리 Paper140에서 학습 off로35초 추론 후 정상 종료하여 실제 수용했습니다. 이름 참조와 최종 런타임 세션이 완전히 일치했고 기존 brain/체크포인트/3008전이/376갱신/off 및 기본 선택이 유지됐습니다. 추론 RNG 진행도 반영됐으며 새 학습은 없습니다. 목록 잠금 실패 후 재시도·준비 자료 제외·게시 전 목록 보존·중복 개정 억제는 원격 회귀 사례로 구분합니다. 새 PPO 갱신 중 자동 저장·손상 제품 세션 복구·전체 월드 성능은 이 실제 시험 범위가 아닙니다.


실행 세션 손상 복구

런타임 세션은 같은 내용의 복사본과 저장 완료 증거를 함께 유지합니다. 복사본을 먼저 저장하고 주 세션을 원자 교체한 뒤, 그 바이트 해시를 담은 완료 증거를 기록합니다. 주 세션이 정상이라면 항상 그 세션을 우선합니다. 주 세션이 손상되거나 없으면 같은 경로의 복사본과 완료 증거가 정확히 일치하는 경우에만 복원합니다. 게시되지 않은 staging 복사본·다른 run/모델·목록의 부팅 기본값을 복구 대상으로 추측하지 않습니다.

복원 전 가중치/critic/Adam·실제 원본 prefix·두뇌 ID/정책 버전/갱신 횟수·난수 상태를 다시 검증합니다. 손상 원본은 덮어쓰지 않고 새 run의 `session-recovery.json`과 백엔드 로그에 복구 출처/해시를 기록합니다. AI의 명시 시작·정지 의사는 기존의 별도 저장을 따릅니다. 주 세션 저장 뒤 완료 증거 기록만 실패한 경우에는 이미 저장한 학습 flag를 되돌리지 않으며 경고를 남깁니다. 이후 복구 증거가 불일치하면 복구를 거절하고 다음 정상 저장에서 다시 기록합니다.

복구 파일이 없는 구버전 세션은 정상일 때 그대로 읽지만 손상 시에는 중지합니다. 관리형 참조 자체 손상, 두 사본/증거의 동시 손상, 체크포인트/원본 경험 손상에는 임의 모델이나 오래된 학습 모드를 선택하지 않습니다. 전체 디스크/전원 장애 복구나 PPO 도중 손실의 수용으로 확대하지 않습니다. 이번 변경은 원격 CI와 실제 격리 Paper140 시험을 통과했습니다. 저장된 AI를 정지시킨 뒤 같은 서버의 주 세션을 손상시킨 경우와 없앤 경우를 각각 재시작했습니다. 두 경우 모두 같은 brain/체크포인트/정책 버전/갱신 횟수/학습 off/RNG·명시 STOPPED 의사가 복원됐고 자동 시작·새 AI 생성은 없었습니다. 손상 원본은 그대로 남겼으며 원래 정상 바이트도 별도 보존했습니다. 준비된 제어 사례이므로 자율 학습 계보나 생존 능력 향상으로 계산하지 않습니다. 완료 증거 불일치·가중치 손상·증거 쓰기 실패의 경계는 원격 회귀 사례이며 실제 디스크 장애 시험으로 확대하지 않습니다.


이름 모델의 추가 학습과 고정 추론

공유 백엔드와 격리 도구의 `--learning on|off`는 가중치 출처와 독립적인 명시 설정입니다. 생략하면 복원한 학습 상태를 유지하고 Fresh는 기존처럼 학습 on으로 시작합니다. `--inference-only`와 함께 지정하지 않습니다. 관리형 수용 도구의 추론 전용 경계를 이 옵션으로 바꾸지 않으며, 외부 학습 백엔드에서만 사용합니다. 이름 목록에서 세션을 고정할 때 실제 선택한 이름도 함께 전달해 자동 저장이 원래 이름이 아닌 현재 활성 이름에 반영되도록 했습니다. 실험 manifest는 실제로 선택된 학습 설정과 명시 override를 구분합니다.

실제 Paper140의 정상 플레이에서 기존3,008전이·376갱신 모델을 별도 이름으로 참조하고 `--learning on`으로128전이를 추가 학습했습니다. 누적3,136전이·392갱신/정책버전98이며 정책망과 가치망이 모두 변경됐습니다. 원본 경험 prefix·새 체크포인트를 검증했고 이름 참조와 종료 세션이 일치했습니다. 원본 모델 목록은 보존했습니다. 이후 새 가중치를 `--learning off`로15초 추론 재개하여 체크포인트/버전/갱신/전이는 그대로, 난수만 진행하고 이름 세션에도 off가 저장됨을 확인했습니다. 초기화·Teacher·아이템 생성·순간이동·준비된 제어 시나리오를 쓰지 않은 정상 학습 사례입니다. 이 작은 추가 학습을 생존 능력 향상이나 모든 월드 자율성으로 주장하지 않으며 미사용 월드 평가는 별도로 기록합니다.

동일 후보의 미사용 월드 야간 평가(seed2026102693, 시작시각13000,180초)는 생존 목표 FAIL입니다. 고정 actor의 실제 가중치 선택/학습 미실행/서버 정상 종료는 확인했지만 좀비에게6회 사망·6회 재생성했고 최종 인벤토리는 비어 있었습니다. 채굴39·제작1·설치4·공격6 등의 입력 성공은 장기 생존/진행 성공으로 계산하지 않습니다. 이 모델을 기존 장기/야간 실패보다 개선된 모델이라고 주장하거나 기본 제품 모델로 승격하지 않았습니다. 기본3,008전이 계보와 별도 후보3,136전이 계보·이전 실패를 각각 보존합니다.

후속 야간 학습(seed2026102605, 시작시각13000)은 정상 플레이256전이를 추가했습니다. 후보는누적3,392전이·424갱신/v106이며 원본경험prefix와새가중치·이름참조를검증했습니다. 학습자료에는적관측153프레임·체력감소38전이·사망7전이가포함됐고공격후보92전이중공격9회가선택됐습니다. 관측완전성플래그는전체0이므로0개체값을확인된부재로해석하지않습니다. 이자료의정책·가치망변화는확인했지만야간생존능력향상은별도미사용월드평가로판단합니다.

야간256전이추가후고정후보를두평가월드에서각180초확인했습니다. seed2026102694는사망0이었지만대기·시선·점프가많고최종인벤토리는비어있었습니다. 이전실패seed2026102693의같은야간예산재평가는좀비7사망·7재생성/최종인벤토리[]로생존FAIL입니다. 종전6사망보다개선됐다고주장하지않으며월드・몹발생・정책샘플링차이를고려해단일비교로통계적퇴행도단정하지않습니다. 두원본/보고서와기본모델·이전후보를보존했습니다. 다음은실제진척과위협대응의학습신호가충분한지분석하는단계이며모든월드완전자율은미완료입니다.

랜덤 월드 회차

새 실험 월드를 시작할 때 `--world-seed` 대신 `--random-world-seed --seed-campaign <공유 비공개 경로>`를 사용합니다. 정책 난수와 독립적인 난수원에서 새 signed64-bit 시드를 뽑으며, 하나의 레지스트리에 학습·평가 예약을 모두 누적해 이전 시드 재사용과 분할 이동을 거절합니다. 입력 기본 계획과 레지스트리의 기존 분할을 함께 보존하고 실제 선택된 확장 계획을 각 실행의 seed-plan.json에 고정합니다. manifest의 seedSelection은 random-per-world-run입니다. 학습과 평가는 같은 레지스트리를 사용해야 하며 손상/기존 잠금/예산 소진 시 새 목록으로 조용히 초기화하지 않습니다.

한 관측마다 다른 월드로 옮기지 않습니다. 한 회차의 실제 상태→행동→다음상태는 같은 월드에서 이어지고, 다음 월드를 시작하는 회차에서 새 시드를 씁니다. 현재 한 회차 안의 사망·재생성은 같은 월드이며 매 사망마다 서버를 갈아끼우는 기능은 아닙니다. 예약 후 실행이 실패한 시드도 예약 목록에 남지만 학습 완료 전이로 계산하지 않습니다. 기존 시드/실패 자료는 재현 근거로 보존하며 새 실험에서 평가 시드를 훈련하지 않습니다.

비동기 응답 사이의 관측

이전 야간256전이에서는 행동 전 적 관측153개에 비해 다음 상태의 적 관측은3개뿐이었습니다. 탐지 갱신 틱과 비동기 응답 틱이 다르면 개체 정보 전체를 비우던 경로를 수정했습니다. 캐시에 있던 개체를 현재 생존/월드/거리/가시성으로 재확인해 현재 보이는 적의 위치·거리·체력은 전달합니다. 오래된 좌표나 가려진 적을 그대로 복사하지 않습니다. 전체 범위의 현재 탐지가 확인되지 않으면 관측 완전성은0/UNKNOWN이며0개체를확인된부재로바꾸지않습니다. 전체월드스캔/정답회피방향/Teacher우선순위를추가하지않고기존같은메인스레드·예산·개체16개한도를유지합니다. 기존v2벡터크기와가중치는그대로재개할수있으며이전실패/원본전이는수정하지않습니다. 원격회귀와실제회차의새전이결과는별도로기록합니다.

실제 랜덤 회차 두 개를 실행해 서로 다른 시드와 서버의 실제 Seed 출력, 기존 가중치 재개, 회차 내 같은 월드 전이, 누적 분할 예약을 확인했습니다. 두 회차에서64전이씩 추가해 후보는3,520전이·440갱신/v110이 됐습니다. 첫 회차는 적 관측이 없었고, 두 번째는 행동 전 적 관측33전이와 다음 상태 적 관측31전이가 기록됐습니다. 이 수치를 생존 능력 향상으로 계산하지 않으며, 별도 랜덤 평가와 기존 생존 실패를 함께 보존합니다.

Paper의 실제 PlayerAdvancementDoneEvent에서 완료 여부와 표시되는 발전 과제인지 확인한 뒤, 활성 학습 전이에 완료1건당1의 추가 신호를 전달합니다. 특정 과제의 순서나 정답 행동을 선택하지 않습니다. 레시피 해금·미완료 기준은 제외하고 같은 AI에서 이미 관측한 완료는 중복 보상하지 않습니다. 학습 off/전이 대기 중 완료도 관측해 이후 on으로 바뀌었을 때 소급 보상하지 않습니다. 게임의 발전 과제를 부여·취소·초기화하지 않으며 사용자/월드 기억과 모델 가중치를 바꾸지 않습니다.
